  2. GitHub: create an account. For pushing, create a token: Settings, Developer settings, Personal access tokens, Tokens (classic), Generate new token, tick repo, copy it. 1.Create a fresh Git repository, store files locally and push to GitHub

Explain the process of creating a fresh git repository and store files locally and in GitHub along with commands.

Git tracks changes in a local repository. GitHub hosts a remote copy. You create the local repository, commit files, create an empty repository on GitHub, link the two with a remote, and push.

  1. Install Git and set your identity once.
  2. Create a folder and run git init.
  3. Add files, stage them (git add) and save a snapshot (git commit).
  4. On github.com click New repository, name it, and leave it empty (no README).
  5. Connect the remote and push.
--global
Save the setting for your user account, so it applies to every repository. Without it, it applies to this repository only.
git init
Turns the current folder into a repository by creating a hidden .git folder.
git status
Shows which files are untracked, modified or staged.
git add <file>
Moves the file into the staging area (the next commit).
-m "text"
Commit message given inline. Without it Git opens an editor.
branch -M main
Rename the current branch to main. -M is move/rename with force.
remote add origin URL
Registers the GitHub URL under the nickname origin.
remote -v
Verbose list of remotes with their fetch and push URLs.
push -u origin main
Upload branch main to origin. -u remembers this link, so later you can type just git push or git pull.

git add, git branch -M and git remote add print nothing when they succeed. If your Git is configured with main as the default, git status says On branch main.

2.Create a text file locally and push it to GitHub

Create one text file in local machine and save it in local repository, push it to GitHub.

>
Shell redirect: writes the text from echo into the file (creates or overwrites it).
push origin main
Send local commits on main to the remote origin.
log --oneline
Commit history, one line per commit (short hash and message).

Refresh the repository page on GitHub and local-file.txt is listed.

3.Create a text file in GitHub and pull it to the local repository

Create another text file in GitHub and pull it into local repository.

  1. On GitHub open the repository, click Add file, then Create new file.
  2. Name it github-file.txt, type some text, click Commit changes and commit to main.
  3. In the terminal pull the change.
git pull origin main
Downloads new commits from main on origin (fetch) and merges them into your current branch.
ls
Lists files. Use dir in Windows CMD.
cat file
Prints the file contents.

Fast-forward means your branch had no new commits of its own, so Git just moved it forward to match GitHub.

4.Create a text file in the main branch and save it in the local repository

Create one text file in main branch and save it in local repository.

git checkout main
Switch to branch main (newer equivalent: git switch main).
git branch
Lists local branches. The * marks the current one.

5.Create a text file in "branch-1" and save it in the local repository

Create another text file in "branch-1" branch and save it local repository.

checkout -b
Create a new branch and switch to it in one step (git switch -c branch-1 does the same).
push -u origin branch-1
Publish the new branch to GitHub and set it to track the remote branch.
branch -a
Lists all branches, local and remote (remotes/origin/...).

6.Merge both files into main, locally and in GitHub

Merge these two files into main branch and do the same in GitHub.

Locally

git merge branch-1
Brings the commits of branch-1 into the branch you are on (main). Add --no-ff to force a separate merge commit.
--graph
Draws the branch structure as ASCII art.
--all
Include all branches, not just the current one.

It is a fast-forward because main had no new commits after branch-1 was created. If both branches had changed, Git would instead print Merge made by the 'ort' strategy. and create a merge commit. If two branches edited the same lines you get CONFLICT: edit the file, delete the <<<<<<< / ======= / >>>>>>> markers, then git add . and git commit.

In GitHub (pull request)

  1. Open the repository, click Pull requests, then New pull request.
  2. Set base to main and compare to branch-1.
  3. Click Create pull request, then Merge pull request, then Confirm merge.
  4. Locally run git checkout main and git pull origin main. Expected: a Fast-forward or merge message listing branch1-file.txt.
The local merge and the GitHub merge give the same result. If you already pushed the local merge, GitHub will say there is nothing to compare. To demonstrate the GitHub merge, do it first (before the local git push origin main), then git pull.

7.Create a Docker container from an image

Explain the process of creating a Docker Container using ... (the end of this question is cut off in the photo).

A Docker image is a read-only template. A container is a running instance of that image. The flow is: get the image, create and start a container, inspect it, then stop and remove it.

docker pull image:tag
Download an image from Docker Hub.
-d
Detached: run in the background and give the terminal back.
--name my-nginx
Give the container a name instead of a random one.
-p 8080:80
Publish a port as hostPort:containerPort. Requests to your machine's 8080 go to port 80 inside the container.
docker ps
List running containers. Add -a to include stopped ones.
docker logs
Print what the container wrote to stdout/stderr. Add -f to follow live.
exec -it
Run a command inside a running container. -i keeps input open, -t gives a terminal. Type exit to leave.
stop / start
Stop or restart the container without deleting it.
rm -f
Delete the container. -f force-removes it even if running.
rmi
Delete an image (only possible when no container uses it).

Task 1

Create a docker container with name "MyPostgresContainer". Set "POSTGRES_PASSWORD" environment variable to "abcd1234". Run the container on port 8844 and pull latest image of "traefik/whoami" into local machine.

-d
Run in the background.
--name MyPostgresContainer
Container name (case-sensitive when you use it later).
-e KEY=VALUE
Sets an environment variable inside the container. Postgres refuses to start without POSTGRES_PASSWORD. All options must come before the image name.
-p 8844:5432
Host port 8844 maps to Postgres's own port 5432 inside the container.
postgres:latest
The image. Docker pulls it automatically if it is missing.
psql -U postgres
Open the Postgres command-line client as user postgres. Type \q to quit.

Task 2

Run 2 containers on 2 different ports 8686 and 8787.

-p 8686:80
traefik/whoami listens on port 80 inside the container. Each container needs a different host port, but both can use 80 inside.
--name
Two containers cannot share a name, so use whoami1 and whoami2.

Task 3

Check following commands and write the differences: a) curl http://localhost:8686 b) curl http://localhost:8687

10.HTTP verbs: GET, POST, DELETE, PUT

Explain following HTTP Verbs: GET, POST, DELETE, PUT.

VerbPurpose (CRUD)BodySafeIdempotentTypical success codeExample
GETRead a resource or a list (Read)NoYesYes200 OKGET /students/1
POSTCreate a new resource (Create)YesNoNo: repeating it creates duplicates201 CreatedPOST /students
PUTReplace or update an existing resource in full (Update)YesNoYes: same request, same final state200 OK or 204 No ContentPUT /students/1
DELETERemove a resource (Delete)Usually noNoYes: after the first call it is already gone200 OK or 204 No ContentDELETE /students/1

Safe means the call does not change data on the server. Idempotent means calling it many times leaves the server in the same state as calling it once. You will see all four working in Q11.

11.Express microservice on Kubernetes, tested with Postman

Write a Microservice to implement above operations for the following data structure Docker and orchestrate it using K8s and test Pod with Postman: { id: Integer, studentName: String, totalMarks: Integer }

A Node.js Express REST API with an in-memory list, packaged as a Docker image, run on Kubernetes by a Deployment (keeps the pod running) and a Service (stable address for it).

Step 1: Create the project

npm init -y
Creates package.json with default answers (-y means yes to every question).
npm install express
Downloads Express into node_modules and records it in package.json.

Step 2: Write the service

express.json()
Middleware that parses JSON request bodies into req.body. Without it POST and PUT bodies are undefined.
students
The in-memory "database": an array of { id, studentName, totalMarks }. It resets when the process restarts.
req.params.id
The :id part of the URL, always a string, so == is used to compare with the numeric id.
res.status(201)
Sets the HTTP status. sendStatus(204) sends status 204 with an empty body.
app.listen(3000)
Start the server on port 3000.

Step 3: Run and test locally first

-X POST
Sets the HTTP method (GET is the default).
-H "..."
Adds a request header. Content-Type: application/json tells Express the body is JSON.
-d '...'
The request body.
In Windows PowerShell, curl is an alias for another command. Use Git Bash, or just test with Postman. Stop the server with Ctrl+C before continuing.

Step 4: Dockerize

FROM node:20-alpine
Base image: Node 20 on small Alpine Linux.
WORKDIR /app
Working folder inside the image. Later commands run here.
COPY package*.json ./
Copy the dependency lists first so Docker can cache the next step.
RUN npm install
Runs at build time: installs dependencies into the image.
COPY . .
Copy the rest of your code into /app.
EXPOSE 3000
Documents the port the app uses. It does not publish it; -p does that.
CMD [...]
The command run when a container starts.
.dockerignore
Keeps your local node_modules out of the image (the image installs its own).
docker build
Builds an image from the Dockerfile.
-t student:1.0
Tag (name and version) for the image. Use a version like 1.0, not latest, so Kubernetes uses your local copy instead of trying to download it.
.
Build context: the current folder, where the Dockerfile is.

Step 5: Kubernetes files

apiVersion / kind
Deployment is apps/v1. Service (and Pod, Namespace) is v1.
app: student
A label. It must match in three places: selector.matchLabels and template.metadata.labels in the Deployment, and selector in the Service. This is how the Service finds the pods.
image
The image to run. Replicas default to 1 and the container port is optional, so both are left out.
port: 80
The port the Service listens on.
targetPort: 3000
The port the container listens on (Express uses 3000).
Forgot the YAML in the exam? Generate it: kubectl create deployment student --image=student:1.0 --dry-run=client -o yaml > deployment.yml (see Q13).

Step 6: Deploy

Docker Desktop Kubernetes: it can use the image you just built, nothing else to do. minikube: run minikube image load student:1.0 first. Any other cluster: push the image to Docker Hub (docker tag student:1.0 YOUR_USER/student:1.0, docker push YOUR_USER/student:1.0) and change the image: line.

apply -f file
Create or update the objects described in the file.
get pods
Lists pods. Wait until READY is 1/1 and STATUS is Running.
get all
Lists pods, services, deployments and replica sets in the namespace.
logs deploy/student
Shows the output of a pod of that Deployment.
port-forward svc/student 8080:80
Forward localhost:8080 on your machine to port 80 of the Service. Keep this terminal open while using Postman.
If STATUS is ErrImagePull or ImagePullBackOff, the cluster cannot find the image. Run kubectl describe pod <pod-name> and read the Events at the bottom. Fix it with the image options at the start of this step.

Step 7: Test in Postman

Click New, then HTTP. Choose the method, type the URL, and for POST and PUT open Body, select raw, change the type dropdown from Text to JSON, paste the JSON, then click Send. Base URL: http://localhost:8080.

That matters in two ways: it is a Java app listening on 8080, and the compose file you download will probably start a Redis container beside it. You do not memorise anything for steps 1 to 4. 13.Kubernetes commands for Deployments, Services and Pods, plus Question 9B

Write commands for creating Deployment, Services & Pods in K8s. Question 9B: Create a k8s service pod and test using the postman: 1. Pull the image from hub.docker.com/r/ssatyab/studentmarkservice 2. Download namespace.yml, deployment.yml, service.yml.

  • Pod: the smallest unit; one or more containers sharing network and storage.
  • Deployment: keeps the wanted number of identical pods running and handles updates.
  • Service: a stable address and load balancer in front of pods, selected by labels.

Create with commands (no YAML needed)

create namespace
A namespace is a named group of resources, like a folder.
run my-pod
Creates a single Pod. --image is the container image, --port the container port.
create deployment
Creates a Deployment. --replicas=3 means keep 3 pods running.
expose deployment
Creates a Service for it. --port is the Service port, --target-port the container port, --name the Service name.
--type=NodePort
Also opens a high port (30000 to 32767) on the node. Default is ClusterIP (reachable only inside the cluster).
-n demo-ns
Run the command in that namespace. Without it, the default namespace is used.

Inspect, scale, update, delete

describe
Detailed info about one object. The Events section at the end explains most errors.
logs
Output of the container in the pod.
scale --replicas=5
Change the number of pods of a Deployment.
set image deploy/x nginx=nginx:1.27
Rolling update: container-name=new-image. The container name is nginx because create deployment names it after the image.
rollout status / undo
Watch a rollout, or go back to the previous version.
delete namespace
Deletes the namespace and everything inside it.

Create with YAML (Pod, bare minimum)

No namespace is given, so this pod goes into default. Deployment and Service YAML are in Q11.
